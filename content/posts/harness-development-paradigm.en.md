# A Toolchain for the Harness Development Paradigm

As AI-assisted development becomes the default, the shape of an efficient workflow matters more than any single model. This is the toolchain I run inside what I call the Harness development paradigm.

## What the Harness paradigm means

It is an AI-centric way of building software, built on three rules:

- **Humans own direction**, AI does analysis and execution
- **Docs are code**: every piece of knowledge lives in a versioned file
- **Small experiments first**: iterate fast, keep what gets feedback

## The tools I actually use

### 1. AI coding agents

Coding agents are now the centre of daily work. The useful ones do not just complete code — they read project context and argue about architecture.

### 2. MCP servers

Model Context Protocol lets an agent reach external tools and data sources, which is where the capability jump actually comes from.

### 3. Automated workflows

Anything repetitive gets handed to a pipeline: fetching, converting formats, generating drafts. If I do it three times, it becomes a script or a skill.

## Practical advice

1. Start with one small project and grow the workflow from real need
2. Record input and output for every experiment
3. Review periodically and delete tools that stopped earning their place
4. Keep learning — the toolchain is only good for a few months at a time

## Summary

The Harness paradigm is not a replacement for developers; it is leverage on individual capability. The tools matter less than the workflow you build around them.
