上个月合并的大部分代码都有 AI 参与，而没有人能告诉你具体是哪些行。真正让人不安的不是"AI 会写代码"，而是：我们习惯的那套代码评审直觉，是为人写的代码建立的——当作者变成一个极其自信的语言模型时，这套直觉会悄悄失灵。

下面是我实际使用的审计流程。五步，不需要任何额外工具，用的都是你手上已有的东西，本周就可以跑起来。

## 第一步：找出 AI 代码画像

AI 生成的代码没有完美的指纹，谁声称有，谁就是在卖东西。用"差分证据"代替：

- **依赖变动**。一个 PR 悄悄加了三个新包，却没有讨论 lockfile 变化——这是信号。AI 工具的优化目标是"能编译 + 流行项目都这么干"，它们天然会去拉 npm / PyPI 上最新最亮眼的包。
- **提交风格断裂**。突然出现大量密集、没有提交信息的推送，或者仓库从"可审阅的 diff"变成"一个巨大的 squash"。
- **注释风格**。AI 注释解释的是"代码做了什么"（"计数器加一"）——最没用的一种。出现一整片这种注释，不是证据，但会告诉你该往哪儿看。
- **测试不对称**。AI 写的"能跑"的代码，往往只有 happy path 测试。合并进来的文件如果除了错误分支全都覆盖到了，值得再看一遍。

这一步的目的不是归因，而是**分诊**：找出最近变更里最可能含有 AI 代码的那 10%，优先审它们。

## 第二步：先审供应链

AI 生成代码最高概率的失败模式不是逻辑，而是它拉进来的**依赖**。当一次变更引入新包时：

1. 看**发布日期和流行度的组合**。一个周下载 400 万、昨天才发布的包，要么是被接管，要么是拼写仿冒（typo-squatting）。AI 模型会很乐意补全看起来正确的 `pip install` 命令。
2. 看**维护者**。你构建现在硬依赖的包，如果只有一个人类在维护，那是一个决定，不是意外。
3. **锁死并审查 lockfile 的 diff**，而不是看包的 README。看清哪些传递依赖进了依赖树。
4. 任何**处理凭据、网络解析或文件访问**的包，都当作"来自互联网的实习生写的"来重新审。

## 第三步：审权限与密钥

AI 写的代码倾向于慷慨授权，因为"能跑"是它的首要目标。排查：

- **权限越界**——明明只读就够，却用管理员凭据初始化 SDK；照抄文档"示例"的云策略。
- **出现在新位置的密钥**——习惯性提交的 `.env` 文件、粘进 git 里配置文件的 token、构建脚本里的凭据。这是 AI 辅助提交里最常见的发现，没有之一。
- **过宽的解析面**——把用户输入直接送进 shell、eval 或 HTML 插值而没有任何边界的代码。AI 模型会以很高的保真度复现训练数据里的注入模式。

如果有密钥扫描器，对 **diff** 跑，而不是只对仓库跑——有意思的泄露都是最近的。

## 第四步：检查 Agent 边界

如果你的 AI 工具链里有 Agent、MCP Server，或任何能替你行动的工具，审计范围就超出"提交"本身。检查：

- **Agent 能碰到什么**——哪些目录、哪些凭据、哪些云权限。先做一遍[《Your AI Agent Is Running as Root》](/blog/ai-agent-permission-management/)里的 `id` 检查：Agent 以什么身份执行，你的攻击面就是什么。
- **暴露了哪些工具**——编辑器自动装的每个 MCP Server 都是另一个工具、另一层权限面。质疑那些你没要的。
- **提示注入卫生**——Agent 读到的任意网页都可能变成给它的指令。假设你的 Agent 可以被重定向，那就给它完成工作所需的最小可达范围。

## 第五步：排序、修复、披露

AI 代码的发现不是都同等重要。按**可利用性**排序，而不是按"看起来多奇怪"：

1. **可远程触达且可利用**——立刻修，按事件处理。
2. **数据暴露**——git 里的密钥、过宽的权限——本周修，轮换凭据。
3. **供应链风险**——可疑依赖——替换或隔离，然后重新锁版本。
4. **正确性与风格**——正常流程里重构。

然后判断是否属于可披露事项。如果你的产品在欧盟《网络弹性法案》（EU Cyber Resilience Act）的适用范围内，**2026 年 9 月 11 日**起，许多产品将承担漏洞报告义务——确认这个发现属于"已被利用"还是"已知漏洞"类别，以及你的组织是否有通知义务。拿不准的时候，把决定记录下来，比事后解释"为什么没记录"便宜得多。

## 检查清单

- [ ] 最近 10% 的合并按"是否含 AI 代码"做了分诊
- [ ] 新依赖：发布日期、维护者、lockfile diff 已审查
- [ ] 权限范围按最小权限原则重新核对
- [ ] 密钥扫描已对最近 diff 执行
- [ ] Agent / MCP 可达范围已记录并最小化
- [ ] 发现已按可利用性排序；披露义务已核查
