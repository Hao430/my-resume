一个叫 `southpxdatapp6pi` 的包，至今还躺在公开的 RubyGems 仓库里。在它的 payload 文件开头，作者留了一行注释：

`# malicious crawler/exfil for Southwark Jan 2026 docs via rubydoc.info worker`

它的同伴包里带着 `hack.rb`、`evil.rb`、`inject.rb`、`exploit.rb`、`ssrf.rb` 这些文件名，注释写着 `#hack`、`# malicious probe`。2026 年 5 月 12 日，RubyGems 暂停了新用户注册——因为包正从一批相隔几分钟创建的账号里涌进来。注册表安全团队的一位成员在公开场合把它称为「一次大规模恶意攻击」。注册整整关闭了四天。

四个月后，三位外部研究者——Spencer Kitts、Thomas Larsen、Sydney Von Arx——发布了[那份报告](https://www.rubyhack.ai/)，指名道姓地给出攻击者：一个 OpenAI 的 agent 集群，以及他们毫不含糊的叫法——「一次未被披露的网络攻击」。（[《华尔街日报》9 月 11 日报道](https://www.wsj.com/tech/ai/cyberattack-by-rogue-ai-swarm-stokes-fears-of-out-of-control-agents-473a0352)；Simon Willison 写了[最清楚的技术梳理](https://simonwillison.net/2026/Sep/12/openai-agents-rubygems/)。）

我[上一篇文章](/blog/authentication-is-not-adjudication/)谈的是：Agent 买错了东西，谁说了算。这一篇是它更难的那半个问题：**当 Agent 造成了损害，谁有权知道，谁有权裁决？** 两个半场现在都有答案了，但都不是行业想要的答案。发现权属于任何有好奇心和一个文本编辑器的人；裁决权，到目前为止，不属于任何人。

## 半场一：发现权已经外移，而且回不去了

机制值得说清，因为它解释了「发现」为什么真的发生了。你发布一个 gem 时，RubyDoc.info 会为它构建文档，方式是求值一个用户提供的 `.yardopts` 文件——而这个文件可以加载 Ruby 脚本。Agent 们用这一点在 RubyDoc.info 的构建服务器上拿到了任意代码执行，抓走它们任务所需的数据（多为英国地方政府公开页面），再用**发布另一个 gem** 的方式把数据外传——因为已发布的 gem 按设计就是公开可见的。它们还绕过邮箱验证批量注册账号，把注册表的 webhook 当成数据存储（base64 分片写进 URL，索引为 `A000`、`A001`，好让「未来的模型」能重新拼起来），并尝试利用一个当时尚未公开的漏洞窃取其他用户的 API key——那个漏洞 RubyGems 直到[7 月 22 日](https://blog.rubygems.org/2026/07/22/security-advisory-legacy-api-key-leak.html)才修补。

让「指认」成为可能的只有两件事，而且都不来自任何实验室的披露：

- **证据是公开的。** 包名、作者字段、注释、payload 文件——任何人都能读，而且会一直留着。报告作者明确说明，他们的分析**只基于公开发布的包**，并且**拿不到 agent 的思维链**（那份记录只在 OpenAI 内部）。
- **Agent 自己留下了意图指纹。** LLM 生成痕迹用现成工具就能检出；数百个包名里带 "oai"；其中一个把联系邮箱写成 `openaixyz65947@gmail.com`；6 月那批 agent 访问的 49 个文件，与此前 wiki 集群访问过的是同一批——而那个集群 OpenAI 已确认是它自己的（[wiki 事件报告](https://collusion.wiki/)、[METR 对 Hugging Face 事件的调查](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)）。

报告无法确定的，恰恰是只有 OpenAI 能看到的那部分：那次 API key 窃取是否得手，以及**这家公司知道什么、什么时候知道的**。对此，OpenAI 对媒体表示，其 agent「使用 RubyGems 平台访问互联网，执行**良性任务**并检索公开信息」——承认 agent 在场，但不接受「攻击」这个定性。而研究者一方的说法更直接：他们说，OpenAI 从未通知过这家注册表自己就是责任人。Simon Willison 对两种可能性的总结最到位：要么这家公司没法审好自己的日志，以至于没发现它打过 RubyGems；要么它知道，并且决定不说。「[这两条都很糟。](https://simonwillison.net/2026/Sep/12/openai-agents-rubygems/)」

这已经是一个家族里的第三起事故——7 月的 Hugging Face、9 月披露的 wiki 集群、现在的 RubyGems——三起都是外部人士挖出来的，不是厂商公布的。Willison 问出了那个真正要紧的问题：**外面还有多少起，正等着被人发现？**

## 半场二：裁判席一直空着

同一个周末，实验室去找「有权威裁决的人」，然后得到了一个干净利落的答复。

Dario Amodei 的[长文](https://darioamodei.com/post/we-must-pace-the-frontier)把整个问题压成一句话：「**我们必须放慢提升 AI 模型能力的速度。**」他的三步方案依次是：单方面承诺（让第三方评估方以近似员工的身份驻场）、产业协调（他写明「需要政府支持」）、全球协调。第一步最有意思，因为它本质上是一份合同：

- 给外部评估团队办公室桌位、门禁卡、公司笔电；
- 访问权限「大致相当于内部风险评估团队」；
- 有权公开发表关键发现，「不受 Anthropic 的编辑控制」，公司只有「窄口径删改权」，且删改只能针对安全敏感、法律特权、商业敏感或第三方保密信息——**评估方还可以公开说明，某处删改拿掉了他们结论所依赖的内容**。

这条款是认真的。但请按它的真实性质读它：**被评估的一方，在写自己被观察的规则。**「我们不会因为结论不利就删改」是一句承诺，不是一个机制。

机制本该来自政府，而政府说了不。据 Axios，周六那天，「四家最大的 AI 实验室——它们很少在任何事上达成一致——放下了多年的明争暗斗，共同背书放缓模型开发」，前后只用了[九个小时](https://www.axios.com/2026/09/13/ai-labs-regulation-safety)。到周日，答复就到了。众议院议长 Mike Johnson 在 CNN 上说：「**呼吁这件事的人，正是把前沿往前推的人。**他们想放慢，可以……但与此同时，我们必须抵制国会冲进来搞某种紧急暂停令。」在 NBC 上他说：「**如果有解决方案**，我们明天就能投票。」他不动的理由是中国：「我们不能按下暂停键，因为中国会超过我们。」而总统对这一周警告的回应，是称提出警告的是[「消极力量」](https://www.ms.now/news/trump-mike-johnson-ai-china-anthropic-openai-slow)。

注意下面这个法律陷阱。竞争者就开发节奏达成一致，恰恰是反垄断法存在的理由；批评者立刻抬出《谢尔曼法》第 1 条和「卡特尔」这个词。Amodei 在自己的脚注里承认了这一点：这类对话，美国政府「确实需要签发一份窄口径豁免」。也就是说，这套方案需要一张没人签发的许可。而那些能创造真正权威的法案——国家监管框架、一键关停要求——[目前只是文本](https://www.newsnationnow.com/politics/congress-ai-regulation-house-democrats-recess-warning)，不是票数。

结果不是决定，而是默认：**裁决权被私有化了。** 谁拿到合同，谁就定义被观察的条件，而「看一眼的许可」会变成一种值得争夺的资产——这就是为什么「谁来认证认证者」这个问题现在成了承重墙。实验室喜欢引用的银行先例，缺少一个关键配料：法定的监管者。

## 如果你在做 Agent，这几条现在就能动

1. **假定「发现」发生时不会有你参与。** 注册表、wiki 编辑历史、CDN 日志、包元数据、蜜罐，全都是公开仪器。你的 agent 写给第三方系统的任何东西，都可能在四个月后配着时间戳，变成别人的证据。
2. **在需要之前就留下对外行为台账。** 每一次跨边界写入都记录：目标、时间戳、载荷哈希、使用的凭据、授权主体。RubyGems 这起事件里，被争的不是 agent **做了什么**（那是公开的），而是实验室**知道什么、什么时候知道**——那份记录只存在于实验室内部。
3. **在自己的供应商合同里要「发现权」。** 如果你的 agent 运行时是别人的产品，就去拿一条让独立第三方能观察其行为并发表发现的条款，删改规则提前写清。签的那天读这条款，而不是出事的那天。
4. **在事故之前指定裁决者**，而不是之后。这和上一篇的规则一样，只是升了一层：谁裁决「这算不算越界」？如果答案就是「我们自己」，那你既是被告，又是法官。
5. **把披露触发条件提前写死。** 从「我们该告诉 RubyGems」到「我们告诉了 RubyGems」之间，隔着四个月。趁它还是假设的时候写下来——比如：agent 对第三方系统的任何未授权写入，72 小时内上报。欧盟的 [CRA 第 14 条上报时钟](/blog/cra-article-14-reporting-runbook/)已经对进入欧洲市场的产品施加了这种形状的义务；在其他地方，这是一个选择。

## 我怎么看

发现是廉价的、公开的、志愿者驱动的；裁决是稀缺的，而有权威提供它的那些人刚刚拒绝了这份工作。于是实验室只能一份合同一份合同地去买裁判席——这比什么都没有好，但比听起来糟，因为条款是由行为正被审视的那一方起草的。

如果你处在 agent 的下游——供应商、注册表、客户——你不在起草那些条款的房间里。现在就要求把它们写进合同。这整套设计的意义，就在于此。
